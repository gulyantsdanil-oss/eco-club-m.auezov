# EcoImpact 5.2 — запуск защищённого экологического паспорта

## Готовые файлы

- **eco-passport.html** — публичная демонстрация на GitHub Pages (без персональных данных).
- **passport-server.gs** — отдельный сервер Google Apps Script с проверкой длинного кода доступа и выборкой только подтверждённых вкладов.
- **passport-portal.html** — защищённая форма, размещаемая внутри Apps Script как HTML-файл с именем **PassportPortal**.

Сервер ещё НЕ развёрнут. Файлы в GitHub сами по себе не открывают реальные паспорта.

## Запуск — владелец закрытой таблицы

1. Убедиться, что таблица Eco Club не доступна публично. Не открывать доступ к ней ученикам.
2. Открыть https://script.google.com, создать отдельный проект **Eco Club — Private Passport**.
3. В файле Code.gs разместить полный текст из passport-server.gs.
4. Создать HTML-файл **PassportPortal** и вставить текст passport-portal.html.
5. В Project Settings → Script properties установить **ECO_SOURCE_SPREADSHEET_ID**: ID закрытой таблицы Eco Club. Не записывать это значение в публичный исходный код.
6. В редакторе от имени владельца выполнить приватную функцию **adminInitialize_()** — будут созданы приватные листы «Паспорт — доступ» и «Паспорт — выдача».
7. Deploy → New deployment → Web app → **Execute as Me**. Ограничить доступ школьным доменом, если возможно; иначе вариант «Anyone» разрешать только при использовании выдаваемых секретных кодов.
8. Скопировать выданную ссылку Apps Script, оканчивающуюся на /exec. Проверить, что без действующего кода данные ученика не появляются.

## Выдача кода участнику

1. В свойствах проекта задать **PASSPORT_ISSUE_NAME** (точное ФИО из вкладов) и **PASSPORT_ISSUE_CLASS** (класс).
2. В редакторе выполнить **adminIssueCode_()**. Код будет помещён в закрытый лист «Паспорт — выдача».
3. Передать код лично его владельцу и удалить строку с открытым кодом после передачи. Лист «Паспорт — доступ» сохраняет только SHA-256 хэш.
4. Новый код тому же ученику автоматически отзывает старый.
5. Для отзыва: указать **PASSPORT_REVOKE_NAME** и **PASSPORT_REVOKE_CLASS**, затем выполнить **adminRevokeCode_()**.

## Важно для безопасности школьников

- Код нельзя передавать в URL, публиковать в соцсетях, хранить в коде GitHub или в открытой Google Таблице.
- Без кода сервер не выдаёт имена, классы, списки, статистику и историю.
- Не выдавать коды учащимся с совпадающими ФИО внутри одного класса до появления уникального ID участника.
- Согласовать использование персональных данных учащихся по правилам школы и требованиям применимого законодательства.
- Неверный, просроченный/отозванный код должен возвращать отказ. В данной версии поддерживается отзыв, но не автоматический срок действия.
- Выбирать из листа «Вклад» только подтверждённые записи; действующие статусы включают «✅ Подтверждено» и «Подтвердждено». Отклонённые записи не учитываются.
- Протестировать код одного ученика, неправильный код, отзыв, мобильную версию и переключение русского/казахского языков.

## Ограничения версии

Текущая авторизация подтверждает владение длинным секретным кодом, а не школьный Google-аккаунт. Нельзя полагаться на Session.getActiveUser().getEmail() для Apps Script, запускаемого от имени владельца: Google может возвращать пустую строку. Для полноценного школьного SSO потребуется отдельная проверяемая сервером система.

Сопоставление существующих записей временно опирается на нормализованное сочетание ФИО + класс. Для устойчивого запуска нужен отдельный постоянный ID участника на каждой записи вклада и формализованная процедура выдачи/отзыва секретных кодов.
