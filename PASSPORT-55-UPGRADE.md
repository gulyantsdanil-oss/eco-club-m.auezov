# EcoPassport 5.5 — безопасное обновление с сохранением выданных кодов

## Важно

Эти изменения **сохранены в GitHub, но не устанавливаются автоматически в Google Apps Script**. Два Apps Script-проекта уже развёрнуты, и обновлять их следует **по очереди**. Не вставляйте административный код в ученическое приложение.

EcoPassport 5.5 добавляет:
- постоянные ID участников в закрытом листе `Паспорт — участники`;
- привязку ID к каждой **подтверждённой** записи вкладов (столбец M листа `Вклад`);
- индивидуальные коды на **180 дней** с датой окончания (столбец G листа `Паспорт — доступ`);
- ID в столбце H листа `Паспорт — доступ`;
- журнал административных действий `Паспорт — аудит`, без самих кодов;
- ручную синхронизацию новых вкладов после подтверждения их принадлежности.

**Существующие коды не отзываются миграцией и не получают срок задним числом:** для них G остаётся пустой. Они действуют до отзыва/замены и помечаются как старые (без срока). Новые выдаются на 180 дней.

## Подготовка

1. Сделайте закрытую резервную копию существующей Google Таблицы через Файл → Создать копию. Не открывайте её для публичного просмотра.
2. Проверьте, что столбец M листа `Вклад` свободен: миграция записывает туда ID.
3. Убедитесь, что нет **разных** учеников с совершенно одинаковыми ФИО и классом. Если есть — остановитесь: сначала потребуется отдельная сверка и ручная схема идентификации.
4. Проверьте подозрительные дубли без ID заявки: автоматический алгоритм **не** решает, какие из них являются ошибками, и не удаляет вклады.
5. Отключите автоматический перевод кода в браузере: скачайте ZIP из GitHub, откройте .gs/.html через Блокнот. Яндекс Браузер ранее переводил JavaScript-переменные и ломал приложение.

## Шаг 1 — сначала обновить ученический сервер

Существующий Apps Script-проект: `Eco Club — Private Passport`.

1. Скопируйте полный текст **`passport-server.gs`** в `Код.gs` ученического проекта.
2. Скопируйте полный текст **`passport-portal.html`** в HTML-файл `PassportPortal`.
3. Сохраните и проверьте отсутствие ошибок.
4. Развернуть → Управление развёртываниями → редактировать **СУЩЕСТВУЮЩЕЕ** развёртывание → Новая версия → Развернуть.
5. Сохраните параметры доступов этого приложения: от имени владельца, вход только пользователей с Google-аккаунтом. **Не** делайте `Anyone (anonymous)`.
6. По старому индивидуальному коду проверьте, что прежние показатели участника не изменились.

Перед обновлением администрации **не выдавайте новые коды**.

## Шаг 2 — обновить отдельную панель администратора

Другой Apps Script-проект: `Eco Club — Passport Admin`.

1. Полностью замените `Код.gs` содержимым **`passport-admin-server.gs`**.
2. Полностью замените HTML-файл `AdminPanel` содержимым **`passport-admin-panel.html`**.
3. Сохраните свойства `ECO_SOURCE_SPREADSHEET_ID` и `ECO_ADMIN_EMAIL` без изменения.
4. Обновите **СУЩЕСТВУЮЩЕЕ** развёртывание новой версией. Параметры: выполнять от имени пользователя, открывшего приложение; доступ **Только я**.
5. Откройте панель под Gmail владельца. Убедитесь, что видна панель миграции.

## Шаг 3 — однократная миграция

1. В закрытой административной панели внимательно проверьте замечания о возможных совпадениях ФИО/классов и спорных вкладах.
2. Нажмите **«Создать ID и привязать подтверждённые вклады»**.
3. Подтвердите действие. Административный сервер создаст приватные листы `Паспорт — участники` и `Паспорт — аудит`, заполнит ID в столбце M листа `Вклад` для подтверждённых записей и привяжет ID к существующим кодам в H листа `Паспорт — доступ`.
4. Проверьте сообщения панели. При успешной миграции общее число старых действующих кодов останется прежним.
5. Повторно откройте существующий ученический паспорт со старым кодом. Сверьте вклад, макулатуру, крышки и историю. Должен появиться короткий номер паспорта вида `ECO-...`.

## Шаг 4 — новые коды и новые вклады

- Через панель админа «Выдать код»/«Заменить код»: новая выдача действует **180 дней**. Код показывается однократно; в Google Sheets записывается только его SHA-256 и дата окончания. Никогда не делайте скриншот с кодом.
- «Заменить код» отзывает старые коды участника. «Отозвать» немедленно блокирует доступ.
- После появления новых подтверждённых вкладов проверьте имена/классы, затем нажмите **«Проверить и привязать новые вклады»**. До синхронизации они не включаются в паспорт с ID.
- Контролируйте агрегированную диагностику: неподтверждённые, тестовые, строки без ID заявки, подтверждённые без ID участника, старые/истёкшие коды.
- Журнал административных действий хранится в закрытом листе `Паспорт — аудит`. Там нет открытых кодов и хэшей.

## Контроль безопасности

- Попытка зайти в ADMIN с другим Gmail — отказ.
- Неверный, отозванный и истёкший код — отказ.
- Действительный код для своего паспорта возвращает только связанные ID-записи.
- Персональный код не привязан к конкретному Gmail: передавайте его только ученику или уполномоченному представителю. Доступ для пользователей Google-аккаунтов не означает проверку личности ученика.
- Убедитесь, что работа с данными несовершеннолетних согласована по правилам школы.
- Открытые коды из **старого** листа `Паспорт — выдача` удаляйте после безопасной передачи, не трогая хэши из `Паспорт — доступ`.

## Если нужна отмена обновления

В каждом Apps Script проекте через «Управление развёртываниями» можно выбрать предыдущую версию. Приватные ID и дополнительные столбцы, созданные миграцией, не мешают старому коду, но сама миграция не является функцией автоматического отката: восстановление данных должно выполняться из резервной копии вручную после проверки.

**Не возвращайте старую версию ученического сервера после того, как начали выдавать 180-дневные коды:** старая версия не проверяет срок действия. При ошибке лучше исправить новую версию до повторной выдачи.
